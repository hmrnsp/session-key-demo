Ilustrasi lengkap proses end-to-end: data apa yang diolah, bagaimana cara mengolahnya, apa yang benar-benar lewat kabel, apa yang diterima, dan apa yang diproses di request/response. Ringkasan: dikirim / diterima / diproses

Handshake
POST /api/session/handshake		 Public key X25519 sementara (polos) + header Validasi key, buat eph server, hitung shared+HKDF, tanda tangani, simpan di store sessionId, serverPublicKey, signature (polos) Verifikasi tanda tangan, hitung shared+HKDF yang sama, simpan di memori
Login
POST /api/auth/login		 Envelope AES {iv,data,tag} dari {username,password} + X-Session-Id Ambil session key, dekripsi & verifikasi tag, cek password (bcrypt), terbitkan token, bungkus response Envelope AES dari {token,user} (IV baru) Buka envelope → simpan token di memori
Get Profile

Catatan keamanan (yang sengaja dirancang begini)

  1. Session key tidak pernah lewat kabel. Kedua sisi menghitungnya sendiri dari shared secret X25519 + HKDF.
  2. Tanda tangan wajib. Client memverifikasi transcript dengan public key yang ditanam; kalau tidak, MITM bisa menukar serverPublicKey dan skema runtuh tanpa gejala.
  3. Forward secrecy. Kunci X25519 ephemeral dibuang setelah dipakai; kunci RSA long-term hanya menandatangani, bukan membentuk kunci — bocornya di masa depan tidak membuka sesi lama.
  4. HKDF wajib. Output mentah X25519 tidak seragam; info = transcript dan salt = sessionId mengikat kunci ke kedua public key.
  5. Tolak shared secret nol (public key tidak valid) sebelum menurunkan kunci.
  6. IV 12 byte baru tiap pesan; decipher.final() memverifikasi auth tag sehingga payload yang diubah di jalan ditolak.
  7. Yang dienkripsi hanya body request & response. Header X-Session-Id dan X-Auth-Token dikirim polos — lapisan ini mengandalkan TLS di bawahnya.
  8. Error middleware (session_missing, session_expired) memang polos (agar client bisa membacanya tanpa kunci); error controller (invalid_credentials, unauthorized) ikut tersegel. Efek samping: di apiClient.js jalur error tidak membuka envelope, jadi pesannya menjadi generik.
  9. Pin saat build, bukan unduh. Public key server ditanam ke source client; mengunduhnya saat runtime membuka celah MITM.
